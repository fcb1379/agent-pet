# 代码与产品方案对齐评审

> 评审日期：2026-08-04  
> 评审范围：`agent-pet` 电脑桌宠、`agent-pet-sf32` SF32LB525 黄山派固件、`桌宠/docs` 产品文档  
> 结论：现有代码适合作为产品 MVP 底座，但产品大方向应收敛为 **Agent 工作伴侣**。

## 1. 一句话方向

> 面向使用一个或多个 AI Agent 的知识工作者，提供一个在电脑与实体摆件上连续存在的 Agent 工作伴侣：电脑端聚合和解释 Agent 工作状态，实体摆件用屏幕、灯光、声音和震动提供低打扰提醒与实体互动。

“可配置 AI”是接入方式，“Agent 工作伴侣”是产品定位。产品不承诺从任意封闭 AI 界面准确读取内部状态，而是根据适配器能力分级呈现可信度。

## 3. 方案与代码的真实匹配

| 产品能力 | 当前代码 | 判断 |
|---|---|---|
| Agent 状态感知 | Codex/Claude hooks 已可用 | 已具备可演示闭环 |
| 多 Agent 观察 | 电脑端和硬件端均支持，硬件最多 12 会话 | 应保留，不能再把产品限制为单任务 |
| 主任务/焦点 | 当前以最高优先级会话为 active | 需要将 active 明确为“焦点会话”，而非删除多会话能力 |
| 电脑审批 | 电脑端已有允许/拒绝闭环 | 保留为效率功能；实体摆件只唤出上下文，不直接审批 |
| 屏幕角色 | 电脑 Electron + 硬件 LVGL 均有 | 已具备双身体基础 |
| 硬件触摸交互 | 板端本地点击已有，尚未回传电脑 | 需要补充双向输入通道 |
| RGB/震动提醒 | 现有 Agent v1 主要同步状态，未定义提醒级别/震动命令 | 需要新增表达命令或扩展状态字段 |
| 扬声器 | 板端音频底座已存在 | 可作为三级提醒和角色播报通道，但需独立验证资源格式与抢占策略 |
| 麦克风 | 配置已启用音频 MIC 能力，但 Agent 功能未开放 | 保留硬件，默认关闭，先做权限与采音指示 |
| 自适应屏幕 | 电脑图片同步固定 336×336；板端 UI 使用固定布局 | 产品要增加资源 manifest 和逻辑画布，现有图片同步作为兼容路径 |
| AI 开放接入 | 当前正式接入 Codex/Claude，bridge 已有状态归一化 | 抽象 Adapter 接口，不立即承诺任意 AI 的深度状态 |
| 断网/断连 | 本地状态文件、BLE 重连和离线快照已有 | 与产品方向匹配 |

## 4. 必须调整的产品大方向

### 4.1 从“单一主任务”调整为“多会话观察 + 一个焦点会话”

代码已经稳定支持多个会话，且硬件 UI 能显示任务数量和活动 Agent。强行改成单任务会丢掉现有能力，也不符合用户可能同时运行多个 Agent 的现实。

新的定义：

- **观察层**：系统可以同时观察多个 AI 会话；
- **聚合层**：电脑端显示会话总览和最高优先级状态；
- **焦点层**：任何时刻选出一个焦点会话驱动角色细节、提醒和快捷唤出；
- **硬件层**：默认显示聚合状态、任务数量和焦点标记，不在小屏上管理完整任务列表；
- **审批层**：所有审批仍在电脑端完成，硬件只触发唤出焦点会话。

焦点选择规则：

```text
用户主动锁定的焦点会话
> 等待用户/审批的会话
> 错误会话
> 最近发生工具执行的会话
> 最近更新的运行会话
> 最近完成会话
> 空闲会话
```

### 4.2 从“泛桌宠”调整为“Agent 工作伴侣”

当前代码的真实价值集中在 Agent 生命周期、审批提醒、会话聚合和开发工作流。硬件 Demo 的多会话状态显示也与此一致。因此：

- 第一阶段不做泛化的情绪宠物或系统桌面监控产品；
- 角色人格作为表达层，不改变 Agent 工作语义；
- 电脑资源监控作为次要情境输入，不成为主产品入口；
- 任意 AI 通过 Adapter 扩展，但首个验证场景保持 Agent 工作流。

### 4.3 从“重新设计协议”调整为“兼容演进协议”

现有 v1 固定 20 字节协议和 JPEG 同步已通过跨仓库测试，应作为 MVP 数据面保留：

- 状态快照：继续兼容 `AP` 固定帧；
- 时间同步：继续兼容；
- 自定义图片：继续兼容 336×336 JPEG；
- 协议 v1 保持单向状态同步和硬件不可审批的安全边界。

新增能力放入 v2 控制面，而不是破坏 v1：

- 能力协商；
- 提醒等级与勿扰模式；
- 震动、声音和语音播报命令；
- 屏幕触摸事件；
- 硬件健康/电源/MIC 权限状态；
- 资源 manifest 和自适应画布；
- 可选双向事件通道。

## 5. 推荐产品形态

### 5.1 电脑端：Agent 状态中枢

保留当前 Electron 结构，后续拆出清晰模块：

1. **Adapter Hub**：Codex/Claude/通用配置适配器；
2. **Session Store**：多会话状态、焦点锁定和历史；
3. **Policy Engine**：优先级、提醒等级、勿扰、权限；
4. **Character Renderer**：角色表达，不直接读 BLE；
5. **Device Service**：v1/v2 协议、连接、资源和诊断；
6. **Control Center**：AI 配置、硬件、资源、隐私和提醒设置。

当前 `StateStore` 可演进为 `SessionStore`；当前 `selectAggregate` 可保留为聚合器，并增加 `focusSessionId` 和用户锁定策略。

### 5.2 实体端：环境化多模态终端

保留当前 LVGL 桌宠页和状态缓存，增加：

- 聚合状态 + 任务数 + 焦点标记；
- 屏幕交互页面；
- 一级/二级/三级提醒执行；
- 勿扰模式仅 RGB；
- 触摸、按键和姿态事件上报；
- 语音播报队列与本地静音；
- 麦克风默认关闭和不可覆盖的隐私指示；
- 设备能力报告和自适应资源。

## 6. MVP 重新定义

### MVP 必须保留

- 电脑端 Codex/Claude 现有 hook；
- 通用 AI 配置入口，至少支持进程/窗口、CLI 包装或结构化日志中的一种；
- 多会话观察和焦点会话；
- 电脑端审批卡片；
- 电脑桌宠状态表达；
- BLE v1 状态/图片同步；
- 黄山派 LVGL 状态页；
- 硬件屏幕和触摸的第一版页面；
- RGB 提醒；
- 震动二级/三级提醒；
- 扬声器提示音和语音播报；
- 麦克风默认关闭、权限页和采音指示；
- 断连离线状态；
- 用户角色资源导入。

### MVP 明确不做

- 硬件直接允许/拒绝 Agent 审批；
- 麦克风声控、语音唤醒和语音输入；
- 马达机械位移动作；
- 手机 App 和云账号；
- 多硬件组网；
- OTA，除非完成可恢复 Bootloader 方案；
- 完整 Lottie/Spine 原生固件解码。

## 7. 代码改造优先级

### P0：产品闭环补齐

1. 统一 desktop 与 SF32 的状态命名和焦点会话字段；
2. 在现有 v1 协议上增加 Reminder/Focus 的兼容映射或 v2 控制面；
3. 增加硬件触摸/按键事件上报，电脑端先只支持唤出焦点会话和切换勿扰；
4. 增加三级提醒策略：界面/RGB、震动、震动+声音；
5. 增加用户可配置提醒等级和勿扰持久化；
6. 增加硬件能力和连接状态展示；
7. 保证已有 85 项桌面测试与硬件协议测试继续通过。

### P1：开放接入和资源系统

1. 将 hook bridge 抽象为 Adapter manifest；
2. 增加通用 CLI 包装器或 Webhook/结构化日志接入；
3. 资源导入统一转换为逻辑画布中间格式；
4. 屏幕 UI 按能力报告适配分辨率；
5. 增加声音资源包和语音播报队列；
6. 增加焦点会话锁定、切换和恢复规则。

### P2：硬件扩展

1. 麦克风功能；
2. 马达机械动作；
3. 电池与低功耗；
4. OTA 和签名升级；
5. 更复杂的硬件触控任务页。

## 8. 现有代码应保留与重构边界

### 保留

- `agent-pet` 的 Electron 桌宠窗口、托盘、资源监控、hook 安装、审批存储和 BLE 图片同步；
- `agent-pet-sf32` 的 SF32 目标、SiFli SDK 锁定、静态协议解析、LVGL 页面、离线快照、JPEG 原子落盘和音频底座；
- 两个仓库当前已通过的协议与单元测试。

### 重构

- `state-store.js`：从纯聚合改为会话库 + 焦点策略；
- `hardware-protocol.js`：保留 v1 编码，增加 v2 能力/控制编码，不直接重写 v1；
- `agent_pet_protocol.*`：保留固定帧解析，新增扩展消息独立模块；
- `app_pet.c`：把固定尺寸常量和状态显示拆为能力适配与逻辑布局；
- `renderer.js`：将提醒策略、硬件状态和角色动画分离；
- `ble-client.js`：加入协议版本/能力协商和事件通道，但保留当前图片传输回退策略。

### 不应做的重构

- 不为了“通用 AI”重写已经稳定的 Codex/Claude hooks；
- 不把所有传感器原始数据持续传到电脑；
- 不把硬件 UI 变成完整 Agent 管理器；
- 不让协议 v2 破坏已验证的 v1 固定帧；
- 不在没有资源预算前让固件原生支持四套动画格式。

## 9. 验收基线

### 代码基线

- `agent-pet`: `npm test` 当前 85 项通过；
- `agent-pet-sf32`: `tests/run_agent_pet_protocol_host_test.ps1` 当前通过；
- 两仓库当前有未提交状态需单独处理，不把 `sdk-submodule-placeholder` 误认为产品功能变更。

### 产品新增验收

1. 同时存在多个 Agent 时，硬件显示聚合状态、任务数和焦点标记，电脑详情可查看全部会话。
2. 用户锁定焦点会话后，普通会话状态变化不抢占焦点表达；焦点失效时按规则恢复。
3. 一级提醒不震动不发声，二级增加震动，三级增加声音/语音，勿扰仅 RGB。
4. 硬件触摸或按键可以唤出焦点会话，但不能直接审批。
5. 已连接设备通过能力报告选择屏幕资源尺寸和可用通道。
6. 麦克风硬件存在但默认关闭，启用状态在电脑和硬件均可见。
7. L0/L1 AI 接入不会伪报 `thinking` 或 `waiting_user`。
8. v1 固定帧与图片同步回归测试继续通过。

## 10. 最终大方向

当前项目不再以“做一个桌宠”作为研发目标，而以以下产品作为共同目标：

> **Agent 工作伴侣：一个面向多种 AI Agent 的本地桌面状态中枢和实体多模态终端。**

电脑端负责接入和解释 Agent、管理多会话、处理审批和维护焦点；实体摆件负责让状态在用户离开 AI 窗口时仍然可感知，并通过屏幕、RGB、震动和声音提供分级提醒。两端共享同一个角色语义，但不共享所有细节。

这个方向最大程度复用现有代码，同时为通用 AI 配置、硬件输入、提醒等级和未来语音/传感器扩展保留边界。

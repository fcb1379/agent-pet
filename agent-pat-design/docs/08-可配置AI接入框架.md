# 可配置 AI 接入框架

> 文档状态：Draft  
> 版本：v0.1  
> 最后更新：2026-08-04

## 1. 目标

产品不绑定某一家 AI。用户可以通过标准适配器或配置方式把不同 AI 工具接入桌宠；Codex 作为首个参考实现。

“可配置任意 AI”表示系统提供通用接入机制，不表示在 AI 没有开放接口时仍能准确读取其内部运行状态。每个接入必须明确声明自己能够可靠观察的状态。

## 2. 接入等级

| 等级 | 数据来源 | 能力 | 可信度 |
|---|---|---|---|
| L3 标准适配器 | 官方 API、插件、事件流、SDK | 精确任务关联、状态、等待原因、完成和失败 | 高 |
| L2 结构化配置 | Webhook、结构化日志、命令包装器 | 根据明确规则映射任务与状态 | 中高 |
| L1 桌面观察配置 | 进程、窗口标题、托盘或文件变化 | 判断应用运行、窗口出现或部分可见状态 | 中低 |
| L0 基础入口 | 启动命令、URI、应用路径 | 启动或唤出 AI，不提供内部任务状态 | 无状态承诺 |

控制中心必须显示接入等级、数据来源、可用状态和缺失能力。L1 推断结果应标为“推测”，不能显示为确定的“正在思考”或“等待授权”。

## 3. 统一能力声明

每个适配器提供 manifest：

```json
{
  "id": "example.codex",
  "name": "Codex",
  "adapter_version": "0.1.0",
  "integration_level": "L3",
  "sources": ["official_event"],
  "capabilities": {
    "task_identity": true,
    "states": ["idle", "thinking", "tool_running", "waiting_user", "success", "error"],
    "waiting_reason": true,
    "progress": false,
    "focus_task": true,
    "cancel_task": false
  },
  "permissions": ["local_event_access"],
  "launch": {"supported": true},
  "focus": {"supported": true}
}
```

适配器不得声明无法稳定提供的能力。配置变更后必须重新验证并更新能力报告。

## 4. 通用配置方式

### 4.1 Webhook

用户或第三方工具向本地端点发送事件：

```json
{
  "adapter": "my-ai",
  "task_id": "42",
  "event": "waiting_user",
  "timestamp": 1785830400000,
  "data": {"reason": "input_required"}
}
```

Webhook 默认只监听本机回环地址。启用局域网访问需要单独授权、令牌和来源限制。

### 4.2 命令包装器

系统通过包装命令启动 CLI AI，并根据进程生命周期、标准输出中的结构化事件或退出码生成状态。包装器必须避免记录提示词和输出正文，除非用户明确配置了所需字段。

### 4.3 日志规则

用户指定日志路径和匹配规则：

```text
匹配事件 -> 统一状态
任务标识提取规则
时间戳提取规则
去重和超时规则
```

日志读取使用最小目录权限，并提供测试页面展示“哪一行触发了哪个状态”。默认不保存匹配到的完整日志行。

### 4.4 进程和窗口规则

可以配置：

- 进程名或可执行文件路径；
- 窗口标题规则；
- 启动命令；
- 唤出窗口规则；
- 应用关闭时的状态。

这种方式只能可靠判断应用是否运行或窗口是否存在，不能单独用于声明 AI 正在思考、调用工具或等待用户。

### 4.5 手动和快捷操作

对于没有可观察接口的 AI，用户仍可配置启动、唤出和快捷键入口。此类接入属于 L0，不参与自动任务状态闭环。

## 5. 状态映射

适配器输出统一 AI 状态：

```text
idle
thinking
tool_running
waiting_user
success
error
unavailable
```

每次状态事件必须包含：

- 适配器 ID；
- 会话 ID 与是否为焦点会话；
- 状态；
- 事件时间；
- 可信度；
- 数据来源；
- 可选的等待或错误类别；
- 可选的唤出任务动作。

不向角色核心传递提示词、完整回复或文件内容。需要显示摘要的未来功能必须单独授权并与状态通道隔离。

## 6. 多会话与焦点会话规则

MVP 可以同时观察多个 AI 会话，但只允许一个焦点会话驱动角色细节：

1. 所有可信会话进入 Session Store 并参与聚合状态和任务数量；
2. 用户可以从电脑端显式锁定焦点会话；
3. 未锁定时按等待用户、错误、最近工具执行、最近运行、最近完成的顺序自动选择；
4. 焦点会话驱动角色详细表现、提醒和硬件快捷唤出；
5. 非焦点会话仍影响聚合总览，但普通变化不抢占用户锁定焦点；
6. 硬件默认只展示聚合、数量与焦点标记，不管理完整任务列表。

硬件端完整任务切换、队列管理和多会话审批属于后续版本。

## 7. 用户配置界面

控制中心的每个 AI 接入项显示：

- 名称、图标和启用状态；
- 接入等级；
- 数据来源和所需权限；
- 能可靠提供的状态；
- 当前连接和最近事件；
- 测试事件与预览角色表现；
- 启动和唤出配置；
- 暂停、编辑、导出和删除。

配置流程应提供模板：Webhook、CLI 包装、日志、进程/窗口和基础启动入口。

## 8. 安全与隐私

- 适配器默认在本地运行，无需账号和云端服务。
- 每个适配器使用最小权限，不能自动获得任意文件、命令或网络权限。
- 自定义命令在保存和首次执行前明确展示完整命令及工作目录。
- 日志规则限制到用户选择的文件或目录。
- Webhook 使用随机本地令牌并限制消息大小、频率和字段。
- 适配器输出视为不可信输入，进入统一事件层前完成 schema、长度和枚举校验。
- 适配器卸载后撤销权限、停止进程并删除密钥；是否保留配置由用户选择。

## 9. Codex 参考适配器

Codex 参考适配器覆盖桌面端、CLI 和 IDE 插件三种形态。三者分别评估并声明能力，不强求状态精度完全一致。每种形态必须列出：

- 可获得的官方事件或本地接口；
- 是否具有稳定任务 ID；
- 是否能区分思考、工具执行、等待用户、成功和失败；
- 是否能安全唤出对应任务；
- 桌面端、CLI 和 IDE 形态的能力差异；
- 无官方事件时的配置接入降级方式。

Codex 特有逻辑不得写入角色核心或联动协议，只存在于适配器内部。

## 10. MVP 验收

1. Codex 桌面端、CLI 和 IDE 插件分别完成接入；其中至少一种形态完成完整可信状态链路，其余形态明确能力与降级边界。
2. 用户无需修改程序代码，可以通过配置接入第二个 AI 或模拟工具。
3. 控制中心准确显示两个接入项的等级、来源和可用状态。
4. L1/L0 接入不会伪报 `thinking`、`tool_running` 或 `waiting_user`。
5. 多个 AI 同时产生事件时，聚合状态、任务数量和焦点选择符合规则。
6. 关闭或删除适配器后，不再采集其状态且相关权限被撤销。
7. 日志和诊断中不出现提示词、完整回复或用户文件内容。

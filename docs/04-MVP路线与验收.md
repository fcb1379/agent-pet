# MVP 路线、验收与决策清单

> 文档状态：Draft（确定项已收敛，剩余选择见《待确认决策清单》）  
> 版本：v0.4  
> 最后更新：2026-08-04

## 1. 推荐 MVP

MVP 只证明一个完整闭环：

> AI 工具状态变化 -> 电脑端统一状态 -> 屏幕桌宠和实体摆件同步表达 -> 用户触摸/按键 -> 两端即时反馈并触发一个安全的电脑动作。

### 1.1 MVP 包含

- Windows 常驻程序、托盘和基本设置。
- Codex 桌面端、CLI、IDE 插件三个参考接入形态，一个通用可配置适配器和一个可控模拟适配器。
- 多会话观察、聚合状态和一个焦点会话；电脑端可查看全部会话，硬件显示数量和焦点标记。
- 用户可选择开启的 CPU、内存、电源和网络状态摘要与展示。
- 屏幕桌宠透明窗口、拖拽、点击穿透切换，以及 7 类 AI 活动状态和设备连接状态表现。
- BLE 发现、安全绑定、重连、能力协商和完整状态重同步。
- SF32LB525 黄山派上的自适应屏幕及屏幕交互、扬声器、震动、麦克风硬件、BLE、RGB、功能键、IMU 手势和环境光自适应。
- 麦克风采音默认关闭；MVP 只完成权限、自检和持续采音指示，不开放用户采音功能。
- 用户导入角色资源包的本地入口和安全校验。
- 互动映射：例如单击唤出焦点会话，长按切换勿扰；MVP 不通过硬件批准任何 AI 操作。
- 基础诊断、日志、固件版本查看和恢复刷写路径。
- 软件设备模拟器与协议自动测试。

### 1.2 MVP 不包含

- 手机 App、账号系统、云同步、多用户和远程控制。
- 摄像头、语音唤醒、语音输入及其他麦克风用户功能。
- 多摆件联动和第三方插件商店。
- 硬件端完整任务列表、任务切换和多会话审批。
- 电池供电产品化和复杂机械结构；板上充电能力只做电气确认。
- 在硬件上显示 AI 对话全文。

## 2. 分阶段计划

| 阶段 | 目标 | 主要产出 | 出口条件 |
|---|---|---|---|
| 0. 产品与板级 spike | 消除 SF32LB525 和体验最大不确定性 | 资源预算、BLE/屏幕/串口/传感器实测、状态动效样片 | 关键能力可行，MVP 范围冻结 |
| 1. 无硬件垂直链路 | 建立可并行开发基础 | 协议 schema、PC Device Service、软件设备模拟器 | 重连/乱序/未知字段测试通过 |
| 2. 开发板闭环 | 打通真实设备 | BLE 固件、能力报告、表达引擎、实体输入 | AI 状态与互动端到端演示 |
| 3. 屏幕桌宠体验 | 形成统一角色 | 角色状态机、屏幕渲染、设置和隐私页 | 两端表现一致且冲突仲裁正确 |
| 4. 稳定与小规模内测 | 验证长期使用 | 升级/恢复、诊断、72 小时测试、埋点摘要 | 达到性能、连接和理解度指标 |
| 5. 自研硬件评估 | 从开发板走向产品 | 功能块冻结、结构/BOM/认证计划 | 决定继续 EVT 或保持开发者套件 |

## 3. 首个演示版本验收用例

1. 首次配对：用户通过实体操作进入配对，电脑完成绑定并读取能力。
2. AI 模拟器依次切换 7 类 AI 活动状态；设备模拟器独立切换连接状态，两端在 1 秒内一致响应且两类状态不会互相覆盖。
3. 真 AI 适配器完成一次思考、工具执行、等待用户和成功流程。
4. 拔掉/恢复连接后，摆件进入离线表现并自动重连；重连后收到完整快照。
5. 用户单击硬件，硬件立即回应，屏幕桌宠随后同步回应且电脑动作只执行一次。
6. 电脑程序 UI 重启，后台设备服务连接不中断；服务重启后能自动恢复。
7. 注入未知动作、过期命令、重复消息、坏分片和存储不足，设备不崩溃且返回明确错误。
8. 应用固件损坏后可通过 CH340N 恢复；OTA 未达到恢复要求前不向用户开放。
9. 开启勿扰后，无声音、高亮闪烁或突然机械动作，等待用户状态仍可辨识。
10. 导出日志不包含提示词、AI 回复正文、文件内容或键盘输入。

## 4. 近期技术任务

### 板级 spike

- 跑通 SDK 的 BLE 安全配对、notify/write 和自动重连示例。
- 实测不同 MTU/连接间隔下小消息延迟和资源传输吞吐。
- 测出显示刷新、动画解码、RAM/Flash 和温升数据。
- 验证 CH340N 的烧录/日志/恢复方案，并核对 Type-C 与 MCU 的数据连接。
- 跑通 IMU 拿起/翻转/摇晃识别、环境光自动亮度，并测地磁受马达和结构干扰程度。
- 验证 TF 卡插入检测、资源读取、热插拔和损坏降级。
- 制作一个本地输入 -> 本地反馈 -> BLE 上报的最小固件。

### 协议与工具

- 将 v1 消息写为机器可读 schema/CDDL，并生成 golden vectors。
- 实现软件摆件模拟器、抓包日志查看器和故障注入。
- 确定动作资源 manifest、哈希、版本和 fallback 规则。

### 产品体验

- 为 7 类 AI 活动状态和设备连接状态分别制作屏幕、灯光、实体显示三通道动效草案。
- 用 5-8 名目标用户做无文字状态识别测试。
- 验证提示频率、亮度、勿扰和长时间陪伴是否造成干扰。

## 5. 必须由产品负责人确认的决策

这些问题会实质改变成本或架构，应在对应阶段冻结：

| 决策 | 推荐默认值 | 最晚时间 | 影响 |
|---|---|---|---|
| 首发系统 | Windows | 阶段 0 | 桌面框架、系统 API、测试矩阵 |
| AI 接入范围 | 可配置多种 AI；Codex 为参考适配器 | 已确定 | 每个适配器按可观察能力声明可靠状态集合 |
| 实体主要表达 | 自适应屏幕 + 扬声器 + RGB + 震动，屏幕支持交互 | 已确定 | 具体显示、音频和震动规格仍需硬件 spike |
| 是否使用电池 | MVP 不使用 | EVT 前 | 电源、认证、结构、寿命 |
| 板载麦克风策略 | 硬件进入 MVP，采音默认关闭；按功能授权 | 已确定 | 启用时必须提供不可覆盖的持续指示 |
| 是否允许硬件批准 AI 操作 | MVP 不允许；未来另做权限模型 | 已确定 | 避免在无上下文硬件上造成安全误解 |
| 产品形态 | 先开发者套件，再决定量产摆件 | 阶段 4 | BOM、结构、认证、售后 |
| 角色资源版权与分发 | 允许用户导入本地资源包 | 已确定 | 需定义包格式、安全校验、资源限制和版权声明 |

## 6. 风险登记

| 风险 | 早期信号 | 应对 |
|---|---|---|
| AI 状态无法可靠获取 | 只能靠窗口/进程猜测 | 优先官方 API/插件；用 `unavailable` 表达不确定性 |
| 屏幕与硬件看起来不同步 | 两端各自维护状态机 | 电脑端单一权威状态，硬件只缓存和执行意图 |
| BLE 重连体验差 | 休眠后需重新配对 | 阶段 0 实测 Windows 后台行为，USB 仅作恢复兜底 |
| MCU 资源不足 | 显示运行后 RAM 紧张 | 先做预算与压力测试，资源分包、降帧或调整硬件 |
| 机械结构拖慢 MVP | 噪音、堵转、电源干扰 | 先完成灯光/显示闭环，动作执行器后置 |
| 桌宠干扰工作 | 提示过多、亮度过高 | 默认克制、聚合事件、勿扰与频率上限 |
| 硬件确认造成安全误解 | 用户以为按键可批准一切 | 权限分级，高风险必须电脑端显示上下文并确认 |
| 升级失败变砖 | 无 A/B 空间或恢复入口 | 阶段 0 验证分区；冻结可恢复刷写路径后再开放 OTA |

## 7. 建议团队分工

- 产品/体验：场景、状态语义、动作语言、隐私和验收。
- Windows/桌面：AI 适配、状态总线、角色引擎、屏幕渲染、设备服务。
- 固件：BSP/HAL、BLE、表达引擎、输入、升级和可靠性。
- 工业/硬件：器件、供电、结构、热、EMC、可制造性和认证。
- 测试：协议一致性、故障注入、稳定性、系统兼容和用户理解度。

即使初期由一人开发，也应保持这些代码和文档边界，避免 UI、BLE、AI 适配和板级驱动互相直接调用。

## 8. 下一次评审建议输出

阶段 0 结束时应更新本仓库并形成以下可签字结果：

- SF32LB525 黄山派板级能力与资源预算表。
- MVP 系统框图和接口冻结版。
- 协议 v1 schema、三组抓包样例和兼容性规则。
- AI 活动、设备连接、用户模式和互动瞬态四个状态域的屏幕/实体动效板。
- 首个 AI 适配器选择与可获得事件列表。
- 原型 BOM、风险、工期估算和 EVT 去留决策。

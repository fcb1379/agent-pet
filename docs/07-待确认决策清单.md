## 1. 使用方式

本文只包含无法由架构、安全原则或现有硬件资料直接确定，且会实质改变产品范围、体验或研发路径的问题。

请在每项下填写“你的选择”和必要说明。推荐项只是当前建议，不代表已经决定。

## 2. P0：开始主 PRD 前必须回答

### DEC-001 首个目标用户

**问题：**首版主要服务谁？

- A（推荐）：每天频繁使用编程 Agent 的个人开发者。
- B：使用各类 AI 办公工具的通用知识工作者。
- C：以桌面陪伴和角色互动为主要诉求的用户。

**影响：**决定核心场景、AI 接入、角色表达强度和成功指标。A 最容易形成明确的“等待确认和完成提醒”价值闭环。

**你的选择：B。**首版面向使用多种 AI 办公和创作工具的通用知识工作者；编程 Agent 用户作为重要子群体。

### DEC-002 首个 AI 工具

**问题：**MVP 首先接入哪个具体工具？请给出产品名和使用形态，例如 Codex 桌面端、Codex CLI、某个 IDE 插件或其他 Agent。

**推荐原则：**必须能获得可信的开始、思考/运行、等待用户、完成和失败事件，并能定位或唤出对应任务。若只能观察进程存在，不能满足当前核心场景。

**你的选择：**产品不限定 AI，提供可配置的 AI 接入框架；Codex 作为首个参考适配器和验证样例。

### DEC-003 产品首要价值

**问题：**以下哪个价值排第一？

- A（推荐）：减少用户主动检查 AI 任务状态的次数。
- B：提供具有情绪和人格的工作陪伴。
- C：通过实体操作提高电脑操作效率。

**影响：**三者都可以存在，但第一优先级决定 PRD 指标。A 对应效率指标，B 对应留存和情感指标，C 对应操作成功率和节省步骤。

**你的选择：A、B、C。**优先级解释为：A 是首要可量化价值，B 与 C 是并列增强价值。

### DEC-004 实体摆件是否是首版必需品

**问题：**MVP 是否必须同时交付电脑桌宠和实体摆件？

- A（推荐）：必须，两端连续性就是要验证的产品假设。
- B：先只交付电脑桌宠，硬件后续加入。
- C：先做硬件开发者原型，不对电脑桌宠体验做完整要求。

**影响：**A 的验证最完整但开发面最大；B 能快速验证 AI 状态价值，但无法验证“两个身体”；C 容易退化为硬件展示项目。

**你的选择：A。**MVP 必须同时包含电脑桌宠与实体摆件。

### DEC-005 MVP 硬件主要输出

**问题：**第一轮用户测试中的实体摆件依靠什么表达？

- A（推荐）：RGB 为必需，小屏为增强；无屏也能完成全部核心状态表达。
- B：小屏 + RGB 均为必需。
- C：RGB + 马达，不使用屏幕。

**影响：**决定状态设计、动画资源、结构复杂度、进度和成本。当前屏幕规格未知，因此 A 风险最低。

**你的选择：**实体摆件必须具备显示屏、扬声器、麦克风和 BLE；屏幕承担主要视觉表达和直接交互。

## 3. P1：交互设计前必须回答

### DEC-006 角色定位

**问题：**角色主要是什么关系？

- A（推荐）：可靠的工作伙伴，带适度情绪表达。
- B：会监督和催促用户的效率教练。
- C：以情感回应为主的陪伴宠物。

**影响：**决定台词、提醒频率、动作风格以及用户对错误和等待状态的感知。

**你的选择：A。**角色是可靠的工作伙伴，带适度情绪表达。

### DEC-007 提醒强度

**问题：**`waiting_user` 多久未处理后是否升级提醒？

- A（推荐）：首次低强度提示，未处理时有限次数逐级增强，勿扰模式不升级为声音或大动作。
- B：只提示一次，完全不追踪未处理状态。
- C：持续提醒直到用户处理。

**还需填写：**首次提示后多久重复、最多重复几次。

**你的选择：**三级提醒加勿扰模式，用户可自行选择提醒等级。一级使用电脑桌宠界面、硬件屏幕和 RGB；二级增加震动；三级使用更强或重复震动并增加声音/语音播报；勿扰模式仅保留 RGB。

### DEC-008 首批实体交互

**问题：**MVP 除功能键外，选择哪两个互动？

- A（推荐）：拿起/放下 + 翻转进入临时勿扰。
- B：拿起/放下 + 摇晃唤出任务。
- C：只使用功能键，IMU 仅采集数据验证。

**影响：**决定 IMU 算法、误触测试、结构摆放方式和用户教学成本。

**你的选择：A，并增加屏幕交互。**首批交互包括功能键、拿起/放下、翻转临时勿扰和屏幕交互。

### DEC-009 桌宠可见性策略

**问题：**电脑桌宠默认如何存在？

- A（推荐）：常驻桌面边缘，默认不置顶，可切换点击穿透；重要状态才短暂置顶或气泡提醒。
- B：始终置顶显示。
- C：默认隐藏，只在状态变化时出现。

**影响：**直接影响干扰度、发现性和 Windows 窗口实现。

**你的选择：A。**常驻桌面边缘、默认不置顶、支持点击穿透，重要状态短暂增强提示。

### DEC-010 是否显示电脑状态

**问题：**CPU、内存、电源、网络等电脑状态在 MVP 中如何使用？

- A（推荐）：只作为角色行为和异常提醒的次要输入，不显示仪表盘。
- B：控制中心提供完整性能面板。
- C：MVP 完全不采集，专注 AI 状态。

**你的选择：**需要显示电脑状态，但由用户选择是否开启、显示哪些指标以及显示位置。

## 4. P2：技术冻结前必须回答

### DEC-011 首发分发方式

**问题：**Windows 软件以哪种方式分发？

- A（推荐）：普通安装包，开机自启可选，本地运行且无需账号。
- B：便携免安装版本。
- C：需要账号和云端服务的正式产品。

**影响：**决定自动更新、权限、后台服务安装和隐私架构。

**你的选择：A。**普通安装包、本地运行、无需账号、开机自启可选。

### DEC-012 是否要求断网可用

**问题：**除 AI 工具本身外，桌宠与摆件系统是否必须在无互联网时工作？

- A（推荐）：必须；本地状态、互动、角色资源、设备管理均离线可用。
- B：允许依赖云端账号、配置或角色服务。

**你的选择：A。**除第三方 AI 服务自身外，桌宠、设备管理、互动和本地资源均须断网可用。

### DEC-013 角色资源来源

**问题：**首版角色视觉资源如何获得？

- A（推荐）：先做一个自有基础角色和固定动作集。
- B：允许用户导入资源包。
- C：首版即支持多个官方角色。

**影响：**决定动画技术、资源格式、版权、配置界面和测试矩阵。

**你的选择：B。**首版允许用户导入角色资源包。

### DEC-014 原型完成标准

**问题：**近期目标是哪一级？

- A（推荐）：可供 5～8 名目标用户连续使用一周的功能原型。
- B：内部端到端技术演示。
- C：接近量产外观和可靠性的工程样机。

**影响：**决定是否优先投入安装、日志、升级、外壳、稳定性和用户引导。

**你的选择：A。**交付可供 5～8 名目标用户连续使用一周的功能原型。

## 5. 已由方案确定、不再等待选择的事项

- 电脑端是角色和 AI 状态的权威源；硬件拥有设备安全状态权威。
- MVP 使用多会话观察与一个焦点会话；硬件不做完整任务管理或多会话审批。
- MVP 不允许硬件直接批准任何 AI 操作，只负责唤出电脑端上下文。
- AI、设备、用户模式和互动瞬态使用四个独立状态域。
- 硬件本地处理传感器滤波和手势，只上报语义事件。
- MVP 硬件包含麦克风，但采音能力默认关闭；用户启用具体麦克风功能时需要显式授权和不可覆盖的采音指示。
- BLE 是产品链路；CH340N 是烧录、日志和恢复链路。
- OTA 未达到可恢复要求前不向用户开放；原型 P0 是有线可恢复刷写。
- 当前产品 MVP 要求硬件带屏幕并支持屏幕交互；底层协议仍保留能力协商，避免未来硬件版本被固定屏幕规格绑定。
- 所有危险、不可逆或需要上下文的操作均回到电脑确认。

## 6. 已补充的实现参数

1. Codex 参考适配器覆盖桌面端、CLI 和 IDE 插件形态；按各形态可获得的接口分别实现和声明能力。
2. 提醒提供一级、二级、三级和勿扰四种模式；具体重复间隔和次数由默认配置加用户自定义共同决定。
3. UI 与角色资源采用自适应分辨率设计，不绑定单一屏幕尺寸；实际硬件能力通过运行时报告获得。
4. 麦克风首版只完成权限、默认关闭、自检和采音指示，不开放声学或语音用户功能。
5. 扬声器首版包含提示音、角色音效和语音播报。
6. 角色创作输入暂支持 PNG 序列、GIF、Lottie 和 Spine；导入后由电脑端转换为标准中间资源及终端资源。

仍需通过体验或硬件测试冻结：提醒默认间隔与次数、屏幕/触控器件、震动执行器规格、语音播报内容来源，以及各资源格式的大小和性能上限。

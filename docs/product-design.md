# AI 桌宠与硬件摆件

> 产品设计文档统一存放在本仓库 `docs/` 目录。硬件固件位于独立的 [agent-pet-sf32](https://github.com/fcb1379/agent-pet-sf32) 仓库。

本仓库用于定义一套由“电脑桌宠 + 实体桌面摆件”组成的产品。当前阶段先冻结责任边界、联动协议、硬件 PRD 和 MVP 验收口径，再进入原型开发。

## 一句话产品定义

一个面向知识工作者、可配置接入多种 AI 的工作陪伴系统。它通过电脑桌宠和带屏幕、扬声器、麦克风与 BLE 的实体摆件连续表达 AI 与电脑状态，并支持自然互动。

## 当前建议基线

产品总原则：**一个角色、两个身体、一个状态核心。**电脑桌宠是主要交互身体，实体摆件是环境化、低打扰的延伸身体。具体定义以[产品框架基准](00-产品框架基准.md)为准。

- 电脑端：智能、状态采集、行为编排和配置中心。
- 硬件端：低延迟输入、稳定表达、断连自治和设备安全。
- AI 接入：不绑定单一 AI；提供标准、配置和基础三级接入，Codex 作为首个参考适配器。
- 主链路：BLE；CH340N USB 转串口承担烧录、日志和调试。Type-C 当前按 5V/2A 供电能力理解，不能据此假定 MCU 原生 USB CDC/DFU。
- 协议：MVP 兼容现有固定 20 字节 BLE v1 状态/时间/图片数据面；新增能力通过 v2 控制面演进，提供能力协商、硬件事件、提醒等级和设备状态。
- MVP：单用户、单电脑、单摆件；支持多 Agent 会话观察，以一个焦点会话驱动角色细节。实体摆件包含显示、扬声器、麦克风硬件和 BLE，先打通“Agent 状态 -> 双端表达 -> 分级提醒 -> 硬件互动回传”。

当前开发板已知具备六轴 IMU、三轴地磁、环境光、MEMS 麦克风、3W 功放、功能键、RGB、TF 卡、充电管理、负载开关、屏幕/触摸 FPC 扩展和马达驱动接口。

## 代码基线

本产品方案对应以下工程：

| 工程 | 路径 | 角色 |
|---|---|---|
| 电脑桌宠 | 本仓库 | Electron 桌宠、Agent hooks、会话聚合、审批、资源与 BLE Central |
| SF32 硬件 | [agent-pet-sf32](https://github.com/fcb1379/agent-pet-sf32) | SF32LB525 黄山派固件、LVGL 桌宠、BLE Peripheral、协议和音频底座 |
| 产品文档 | 本仓库 `docs/` | 产品框架、PRD、协议演进和验收基线 |

代码评审结论见[代码与方案对齐评审](10-代码与方案对齐评审.md)。

## 暂不承诺

语音助手、摄像头视觉、多设备组网、完全离线大模型、手机 App 和开放插件市场不进入首版。架构保留接口，但不提前承担交付成本。

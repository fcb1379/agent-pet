# 上位机本地实时语音转写

## 1. 功能范围

当前阶段实现上位机侧链路：录音模块产出音频分片，上位机把当前录音的完整前缀周期性提交给本机 STT，并把最新文字显示为可编辑的“对话输入”。暂不修改硬件采集和 BLE 音频通道，也不自动把文字提交给 Codex 或 Claude Code。

Windows x64 发布包内置 whisper.cpp 1.9.2 CPU 运行时、多语言 `base` 模型和 Ogg Opus WASM 解码器。应用启动时会自动完成以下工作：

1. 检查随包运行时和模型；开发环境缺失时自动下载固定版本并校验摘要。
2. 为服务分配随机回环端口，以隐藏窗口方式启动 `whisper-server`。
3. 等待模型加载完成后开放录音接口；服务异常退出时最多自动恢复三次。
4. 应用退出时同步停止服务。

收到 Ogg Opus 后，上位机会在进程内解码为 whisper.cpp 可直接读取的单声道 16 kHz WAV，再提交给本机服务。用户不需要安装 Python、FFmpeg、whisper.cpp，也不需要配置模型路径、服务地址、语言或端口。托盘菜单只保留启停、状态、音频测试和清空转写稿。

## 2. 隐私与资源校验

服务只监听 `127.0.0.1`，并使用每次启动动态分配的端口。录音请求只允许发往回环地址且禁止重定向，因此音频不会发送到公网。

构建和首次缺失恢复使用固定下载地址，并验证：

- `whisper-bin-x64.zip` 的 SHA-256；
- `ggml-base.bin` 的 SHA-1。

`npm run dist:win` 会先执行 `npm run prepare:stt`，再把已校验的运行时作为 `extraResources/stt` 打入 Windows 发布包。开发环境执行 `npm start` 或 `npm run dev` 时也会自动准备资源。

## 3. 录音模块接入接口

渲染进程通过 preload 暴露的接口接入录音数据：

```js
const runtime = await window.agentPet.getLocalSttRuntimeStatus();
if (!runtime.ready)
{
    // 正常只会发生在应用刚启动、模型仍在加载时；稍后再开始录音。
    return;
}

await window.agentPet.startLocalTranscription({
    mimeType: "audio/ogg; codecs=opus"
});

await window.agentPet.appendLocalTranscriptionChunk(opusOggChunk);

const result = await window.agentPet.finishLocalTranscription();
// result.text 为最终转写稿
```

用户取消录音时调用：

```js
await window.agentPet.cancelLocalTranscription();
```

运行环境状态也可以订阅：

```js
window.agentPet.onLocalSttRuntimeUpdate((runtime) => {
    // idle / preparing / starting / ready / restarting / error
});
```

接口约束：

- 一个时刻只允许一个转写会话；
- 单个分片不超过 1 MB，单次录音累计不超过 32 MB；
- 分片拼接后必须是可解码的完整音频前缀；Ogg Opus 第一页必须包含 `OpusHead`/`OpusTags`；
- 原始 Opus packet 必须先封装为 Ogg Opus，不能按任意字节切片；
- 推荐硬件侧复用现有录音封装，传入 `audio/ogg; codecs=opus`。

## 4. 实时策略

默认每 1.5 秒最多发起一次识别。每次提交从录音开始到当前时刻的完整前缀，因此 STT 返回的是可直接替换的最新全文，不需要推测 token 边界。请求执行期间的新分片会合并到下一次请求，避免并发推理堆积。

结束录音时会立即刷新尚未识别的数据；如果已有请求执行中，会等待该请求完成后再判断是否需要最后一次刷新。界面在录音和识别期间只读，完成后允许用户修订和复制。

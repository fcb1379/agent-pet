# SF32LB525 黄山派开发板能力评估

> 硬件基线：芯片完整型号为 `SF32LB525`，当前 SiFli SDK 固件构建目标为 `sf32lb52-lchspi-ulp`。芯片型号用于资料、BSP 和器件验收；构建目标用于固件编译与烧录。

## 1. 输入依据

本页依据当前提供的开发板外设能力表整理。它能确认器件或接口存在，但不能替代原理图、BOM、PCB 网络、配套屏幕资料和实机测试。诸如麦克风型号、马达驱动拓扑、屏幕控制器和 Type-C 数据走线仍需进一步资料确认。

## 3. 推荐硬件能力分级

### Level 0：底层联调原型

- RGB 表达。
- 功能键交互。
- IMU 姿态/手势交互。
- 环境光自动亮度。
- BLE 联动。
- CH340N 烧录、日志和诊断。

这一级足以提前验证电脑与实体角色的底层联动，但不满足当前产品 MVP 的用户测试标准。

### Level 1：当前产品 MVP

- 增加 FPC 配套屏幕和触摸。
- 增加扬声器、提示音和角色音效。
- 保留麦克风硬件并完成默认关闭、权限和采音指示闭环；具体采音功能另行确定。
- TF 卡存储角色及动画资源。
- 增加震动执行器并完成两档强度/节奏提醒；其他机械动作后置。

### Level 2：后续高风险探索

- 语音播报、语音唤醒或语音输入。
- 电池供电和移动场景。
- 地磁方向玩法。

这些能力各自引入隐私、EMI、功耗、结构或认证成本，不进入 MVP 主链路。

## 4. 对责任边界的新增约束

### 4.1 IMU 和环境光必须在硬件本地预处理

硬件不应持续把六轴原始采样流发给电脑。固件完成滤波、坐标校准和手势识别，只上报 `picked_up`、`put_down`、`flipped`、`shaken`、`orientation_changed` 等事件。调试模式才允许限时原始流输出。

环境光同样在本地做滤波和亮度闭环。电脑端只能设置亮度策略、上下限和勿扰模式，不能以高频命令驱动亮度。

### 4.2 麦克风必须有独立权限域

- MVP 固件启动时不初始化麦克风采集链路；只有用户为具体功能授权后才按需初始化。
- 未来能力协商同时报告 `present`、`enabled`、`policy`，不能只报告“有麦克风”。
- 任何启用都需要电脑端显式授权和硬件持续可见指示；指示不能被普通角色动画覆盖。
- 默认只允许本地声学特征事件。上传原始音频或语音数据属于另一产品范围。

### 4.3 TF 卡只存资源，不做系统唯一依赖

设备内部必须保留最小安全资源：配对、离线、错误、升级和恢复表现。无卡、坏卡或资源包损坏时仍能启动、连接和升级。TF 卡上的资源 manifest 需要签名/哈希、版本和大小限制。

### 4.4 马达与地磁不能独立验收

马达通电会产生电源扰动、机械振动和磁场，可能同时影响 BLE、音频、IMU 和 MMC5603NJ。马达功能验收必须包含这些交叉测试；地磁不应成为产品关键流程的唯一输入。

## 6. 下一批所需资料

为了把“器件存在”升级为“可冻结的硬件规格”，下一步需要：

1. 开发板完整原理图和 PCB/引脚分配。
2. 黄山派具体版本、SF32LB525 子型号、内存和 Flash 配置。
3. 22Pin 配套屏幕扩展板型号、LCD/触摸 IC 和分辨率。
4. 马达驱动原理图、推荐马达类型与最大持续/峰值电流。
5. MEMS MIC 型号、PDM/I2S/模拟接口和功放输出电路。
6. Type-C、CH340N、烧录/复位和 MCU USB 网络连接图。
7. 电池推荐规格以及 AW32001ECSR 的实际充电电压配置。
8. WS2812 数量、位置和环境光传感器位置。
